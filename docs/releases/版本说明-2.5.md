# 2.5 · 音乐准备与档案揭示同步

日期：2026-10-11。此编号用于功能迭代记录。

曲库先建立完整元数据索引，用户打开音乐档案时才准备选中音频。准备期间文字保持黑条遮盖，场景与返回操作可用。音频就绪后启动原有解密和文字揭示，最后一帧发出播放指令。加载失败保留黑条并提供重试；返回、重新选曲和切换内核使旧请求失效。

- 内核切换等待旧输出停止；停止失败时保留原内核。媒体键跟随当前内核，VLC 暂停后继续保留进度。
- VLC 后台状态查询复用同一请求，准备和控制期间暂停轮询；播放命令使用服务端回执确认结果。丢失回执或连接后仍记住可能存在的输出，恢复连接并确认停止后才切换内核。
- 浏览器和 VLC 共用列表、单曲、随机队列规则；VLC 在音乐面板关闭时仍检测自然结束并接续。
- 扫描以完整事务保存索引和封面。旧目录选择、旧扫描及旧恢复任务不会回填新曲库；新来源重新读取元数据，同来源重复扫描可增量复用。
- 搜索覆盖全部曲目，面板每批显示 240 条，可继续浏览。封面图集沿用可见槽位复用，对象 URL 另有 384 项预算及使用租约。
- PWA 首次保存核心资源，其余字库按需缓存，可在设置下载完整离线字库。发行清单仍保留全部文件。
- CI 增加 Windows 浏览器与 VLC 验证，下载 VLC 时验证官方 SHA256，失败保留诊断证据。

环境、执行命令、测试结果和实际出声延迟边界见 [验证记录](../../verification/MUSIC-ACCESS.md)。远端检查结果以 GitHub Actions 为准。
