# 音乐播放与曲库稳定性验证

日期：2026-10-10。对应版本 0.1.2（原 2.4）。环境：Windows 64 位、Node.js 24.18.0、Edge 154.0.4258.62、VLC 3.0.21 Vetinari。

## 六项改进

| 问题 | 当前行为 |
| --- | --- |
| 切歌/停止的异步竞态 | 播放请求序号覆盖文件读取、音频上下文恢复和原生播放承诺；暂停、停止、销毁使旧请求失效。切歌立即静音旧音源，旧错误和封面不覆盖新曲目。 |
| 上一首/下一首方向 | 面板上一首向前、下一首向后，浏览器、VLC 和媒体键按同一方向；VLC 离线不转交浏览器播放器。 |
| VLC 清理隔离 | 自检和页面套件均按所启动进程的 PID 清理进程树。目录维护中已移除按名称结束所有 VLC 的逻辑，本轮实际验证独立 VLC 实例存活。 |
| 桥接断线 | SSE 实际打开才算连接；事件流错误、状态请求失败、VLC 离线或无帧超时会通知离线。500ms–8s 退避重连，主动断开/销毁取消重试；旧查询的迟到失败不误断开新状态。 |
| 配乐与重连曲库 | 断线清空播放状态并按偏好恢复背景配乐，浏览器仍播放时保持让位；重连读取实际 VLC 状态与新曲库，旧/失败的加载不覆盖新内核的数据。 |
| 封面与大分组 | 可见帧先固定封面分配，再更新 GPU 索引；离屏槽位回收，分配票号/曲库代际阻止旧图回填。源 URL、面板及档案缓存随换库/重扫/还原更新。档案槽位改为独立记录编号，行列坐标独立反查。 |

## 验证边界

- 浏览器与 VLC 页面验证使用无头 Edge 和软件渲染；验证状态、接口、真实曲目 ID 与解码频谱，不能代表真实设备的听感或正常 GPU 下的帧率。
- VLC 页面套件另有 6 秒正弦曲的直接播放观察，本轮观察值为 `stopped`，不计入 16 项通过结果；真实播放进度与解码通过独立协议自检验证。
- 测试音频来自项目原创配乐与生成音频，不读取私人曲库。浏览器配置、即时截图与样本位于被忽略的 `.local/`。
- 图集仍保留 255 张**同时可用**的真实封面预算，超密/超宽视图优先画面中心，外围暂用占位图；滚动后可继续获取槽位，整库总曲目数不受 255 限制。
- 本轮修改保存在本地工作区；未对已发布 GitHub 仓库执行提交或推送。
