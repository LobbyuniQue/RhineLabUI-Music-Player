## 0.0.5 相对 0.0.4 的变化

### 一、修复：回到主界面律动不动（用户反馈）

症状：音乐面板里能看到律动，回到主界面就静止。排查出**两个同链根因**（均只影响浏览器内核，VLC 内核的桥接包络由帧循环直接驱动，不受影响）：

1. 浏览器内核的 `musicPlayer.tick()`（读 AnalyserNode → 产出频段与响度）由 `MusicPanel.tick()` 转发，而面板 tick 开头是 `if (!this.mounted) return`——面板一关 tick 停走，频段包络冻结在最后取值；纯包络驱动的律动（响度／波频）在三维场景里即表现为静止。
2. `pause()` 会把 `this.active` 置 false，而 tick 自守条件含 `!this.active`——暂停瞬间同样冻结（此前能「降温」只是 Web Audio 内部 0.68 平滑常数在替包络衰减）。

修复：`player.tick` 改由 `main.ts` 帧循环直接调用（与面板挂载解耦，自身有空转保护）；tick 自守去掉 `!this.active`（包络自负衰减，`isPlaying()` 已作为 enabled 传入）；`dispose()` 显式归零。

附带修复（同版验证暴露）：播放行高亮此前只在面板自身操作后更新，浏览器内核「下一首/上一首」与外部发起（MediaSession、调试面）的换曲不会刷新——`syncPlayingRow` 改为幂等（变化时才滚动与刷新播放条），并由面板 tick 每帧跟随。

### 二、新功能：档案随音乐波频律动（用户要求）

新增第五种律动风格 **波频律动**（`ripple`，设为 0.0.5 新装默认）：振幅由整体响度驱动，频谱成分决定波纹形态——低频占比高波纹稀而慢、高频占比高波纹密而快，环形波从屏幕中心向外扩散。`rhythmDisplacement` 因此增加屏幕 y 坐标（与 x 共用同一次投影，零额外开销）。原版／连续频谱／层叠流波／响度律动全部保留可切。

### 三、验证脚本修正（与产品无关的 harness 问题）

- 无头 Edge 会在唯一音频暂停后节流页面（rAF/定时器停摆，已用裸 3s setTimeout 实测），两个验证脚本加反节流标志以模拟真实可见页面；包络衰减按帧推进，低帧率下断言改为趋势轮询。
- 注入的 File 设固定 `lastModified`（复用判定按大小+修改时间，否则重扫必然全量重解析）；重扫断言前先 `restore()`（此前测的是「未恢复即重扫」的必然失败路径）。
- 正弦短音强制单曲循环，消除列表循环下读错曲目的竞态；暗色段播放行高亮改 Node 侧轮询；环境漂移断言更新（fixture 曲数 4→5、0.0.3 键盘光标初值）。
