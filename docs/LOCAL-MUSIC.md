# 本地音乐检索与播放

2026-10-14 更新（0.1.5）。主界面「LOCAL MUSIC」提供歌单预设、切换、检索与播放；解码由用户所选的浏览器或 VLC 内核承担。

## 文件夹与歌单

每个歌单最多 1000 首。音乐面板填写名称并添加文件夹；浏览器内核用目录选择器，VLC 内核填写本机目录路径。预设下拉切换当前歌单，删除或重命名预设不修改音乐文件。

目录超过 1000 首时，软件先询问「自动拆成多个歌单」或「返回自行整理」。自动分卷仅按排序后的文件路径建立范围，保留末卷剩余歌曲，不移动文件；每次只打开当前卷的文件读取标签与封面，完整音频在播放时读取。新增、删除或改名可能改变重新扫描后的分卷边界。目录不可用、权限拒绝或超限未确认时，保留原曲库。

浏览器目录预设保存在本机，切换可能再次要求读取授权；文件选择回退只能在当前会话切换分卷，刷新后需重新选择。VLC 在成功切换后将 root/part/split 记入 `.tools/music-playlist.json`，启动根目录记入 `.tools/music-root.txt`；新启动传入另一个目录时不套用旧分卷。

音乐档案先建立完整元数据索引，打开 `ACCESS FILE` 时才准备选中音频。完整动画与减少动画使用不同的起播时机，浏览器和 VLC 两条路径遵循同一策略：

| 动画设置 | 读取、显示与起播 |
| --- | --- |
| 完整 | 点击加载 → 文字保持黑条遮盖 → 音频就绪后运行揭示动画 → 揭示结束帧调用播放；保留场景与返回，失败保持黑条并提示重试 |
| 减少 | 点击加载并直接显示文字 → 音频就绪后直接播放；加载及失败均不添加黑条，不等待动画结束帧 |
| 自定义 | 「模型解密」或「正文揭示」仍开启时使用完整流程；两项均关闭时直接播放。其余动效开关不决定播放策略 |

直接播放仍需要文件读取与内核准备完成，不提前解码整库音频。失败可重试，返回或重新选曲会取消旧准备。`SUPER PERFORMANCE` 调整画质，保留当前动效及播放策略。音乐面板中的播放按钮保持直接播放。

若加载或揭示期间有效动效设置变为直接播放，当前请求立即清除文字黑条，已就绪的音频立即起播，未就绪的音频继续读取后起播；再开启完整动画从下一次点击生效，不重新遮盖文字或重复播放。正常打开设置面板仍会取消未完成的档案播放请求，随后点击采用新的设置。

完整动画的结束帧同步指播放调用；VLC 和声卡存在通信、缓冲延迟，不能保证实际出声采样同步。两种策略的验证记录见 [音乐动画策略验证](../verification/MUSIC-ANIMATION-POLICY.md)。

检索包含全部曲目，面板分批显示，每批 240 条，可继续加载。两种内核支持列表循环、单曲循环、随机播放，系统媒体键跟随当前内核。切换内核先确认旧输出停止；若 VLC 断线且无法确认停止，恢复连接后再切换。

## 两种播放内核

| 内核 | 说明 | 适用 |
| --- | --- | --- |
| **VLC 桥接**（推荐） | VLC 解码并播放，支持它认识的全部格式；网页显示曲库、控制播放、接收频谱 | 本机已获取 VLC 时。格式支持等于 VLC 发行版的支持范围 |
| **浏览器内核** | 网页直接读取所选目录并用浏览器解码（File System Access API） | 未运行桥接服务、或使用线上托管版本时 |

在「设置 → 本地音乐 → PLAYBACK KERNEL」切换。默认浏览器内核；连接过 VLC 后会把选择、端口与令牌记在本机，下次启动自动重连。

## 一、准备 VLC

VLC 不随项目分发，需要时由脚本获取官方发行版：

```powershell
cd RhineLabUI
node scripts/fetch-vlc.mjs          # 下载 vlc-3.0.21-win64，校验官方 SHA256 后解压
```

- **安装位置**：项目路径为纯英文时放在 `.tools/vlc/`；项目路径含中文等非 ASCII 字符时自动改放到 `%LOCALAPPDATA%\RhineLab\vlc`，并在 `.tools/vlc-location.json` 记录位置。
- **为什么在意路径**：VLC 的 Lua 控制接口用旧版 ANSI API 解析自身模块路径，装在含中文的目录下会加载失败（表现为控制接口无响应）。媒体文件本身放在含中文的路径没有问题，已实测。
- **许可证**：VLC 发行版为 GPLv2+（libVLC 为 LGPLv2.1+）。本项目以独立进程调用，不链接、不修改；仅在用户本机使用。若随发行包分发 VLC 二进制，需同时提供其源码获取方式。

## 二、启动方式

### 推荐：统一入口

```powershell
cd RhineLabUI
启动莱茵科技.cmd "D:\Music"
```

或直接运行：

```powershell
npm run start:all -- --root "D:\Music"
```

统一入口会按需安装依赖、获取 VLC、选择空闲端口，同时启动网页和 VLC 桥接，并打开浏览器。音乐目录会保存到 `.tools/music-root.txt`；下一次双击入口即可复用。没有目录记录时，交互终端会询问目录，直接回车则只启动网页。

桥接端口和本次启动令牌通过一次性本地 URL 交给网页。页面消费后会用 `history.replaceState` 清除 URL 中的端口、令牌和引擎参数，并把当前标签页的临时交接凭据放在 `sessionStorage` 中，支持刷新后继续连接；关闭标签页后凭据随会话释放。临时令牌不会写入长期 `localStorage` 偏好。

统一入口支持：

- `--no-music`：只启动网页
- `--bridge-only "D:\Music"`：只启动 VLC 桥接，兼容旧的分离式启动
- `--no-open`：启动服务但不自动打开浏览器
- `--port 8788`：指定桥接起始端口（会同时检查控制与 PCM 端口）
- `--web-port 5173`：指定网页起始端口
- `--vlc <路径>`、`--aout <输出模块>`、`--verbose`：传给桥接服务

### 兼容入口与直接桥接

- [`启动终端.cmd`](../启动终端.cmd)：只启动网页。
- [`启动音乐服务.cmd`](../启动音乐服务.cmd) `"D:\Music"`：只启动 VLC 桥接；需要手动在网页设置中填写端口和令牌。
- 直接运行桥接：

```powershell
node --experimental-strip-types scripts/vlc-bridge.mjs --root "D:\Music"
```

直接桥接启动后会打印监听地址与**本次启动的令牌**，例如：

```
[bridge] listening http://127.0.0.1:8788  (token 3f9c…)
[bridge] vlc control port 8790 · PCM tap port 8789
[bridge] library: 128 tracks (added 128, reused 0, failed 0, 412ms)
```

安全边界：只监听 `127.0.0.1`，除 `/api/health` 外都要令牌；网页只能引用桥接扫描结果里的曲目 id，**不能传任意路径**。统一入口的令牌每次启动重新生成，并且只通过本机一次性 URL 交接。

## 三、在网页中使用

使用统一入口时，网页会自动选择 **VLC 桥接**、连接当前端口并载入曲库；不需要打开设置或复制令牌。进入导航「LOCAL MUSIC」即可检索、播放；在音乐档案库中点击当前档案的 `ACCESS FILE` 会同时打开详情并播放对应歌曲，设置 → 本地音乐仍可调整分组、行距和律动方式。

使用兼容入口或直接桥接时：

1. 设置 → 本地音乐 → 播放内核选择 **VLC 桥接**
2. 填入桥接输出的端口与令牌，点「连接桥接」
3. 连接成功后曲库即来自桥接扫描的目录；导航「LOCAL MUSIC」检索、播放
4. 「重新扫描」让桥接重扫目录（增量：按大小与修改时间复用已解析的标签）

播放行为：VLC 出声；网页镜像播放/暂停/进度/音量，系统媒体键由 VLC 处理；本地音乐播放期间背景三轨自动让位，停止后恢复。

## 四、曲库与动画

- **音乐档案阵列（2.0）**：顶部导航的「ARCHIVE 档案库 / MUSIC 音乐库」按钮把主界面档案阵列切换成曲库视图——每首歌是一份档案，卡片正面贴该曲封面（无封面用品牌占位图）；每一列为同一专辑、同一歌手或同一首字母（在 设置 → 本地音乐 → ARCHIVE GROUPING 切换），列数=分组数横向无限循环。2.2 起封面标签与详情以歌曲名为主行/大字号，歌手与专辑为次行/小字号；设置 → 本地音乐 → ARCHIVE SPACING 可将音乐卡行距在 0.62 至 8 之间调节（默认 4.05），实时预览并持久化。可见性候选固定覆盖整个支持范围，不按音乐模式动态重算；莱茵档案和原片开场仍固定使用 0.62。顶部组名、底部列名、悬停曲目名、选中曲目信息（艺术家/专辑/年份/格式/时长）都随档案联动；详情页展示曲目全部元数据并可 EXPORT 曲目信息文本；检索弹窗在音乐模式下按曲名/艺术家/专辑检索。选中列记忆按模式独立保存，随时切回莱茵档案。中文歌手的首字母按拼音归类。
- **索引**：浏览器内核把索引与封面缩略图存在本机 IndexedDB；VLC 内核的曲库来自桥接（标签解析复用同一份 `src/music-metadata.ts`）。
- **频谱**：桥接把 VLC 解码后的音频旁路为 PCM（`s16le` 44.1kHz 立体声），计算成与壁纸宿主同构的 128 样本频谱，经 SSE 送到网页，驱动既有的档案阵列律动与频谱显示。因此**任何 VLC 能播放的格式都能带动动画**。
- **律动方式**：设置 → 本地音乐 → MUSIC REACTION 提供七种——原版／连续频谱／层叠流波／响度律动／波频律动／**宽频律动**／**高频微光**。宽频律动以平滑低频包络驱动宽阔鼓点起伏；高频微光以中高频细节驱动低幅空间闪动，二者都经过视觉层平滑，避免卡片抖动。波频律动让频率成分参与塑形——响度决定振幅，低频让波纹稀而慢、高频让波纹密而快，环形波从屏幕中心向外扩散。所有样式保留快攻慢放与暂停回落，律动在主界面和音乐面板中都生效。
- **减少动态效果**：音乐档案直接显示文字并在音频就绪后起播；关闭「本地音乐驱动档案律动」后阵列不再响应节奏。自定义设置中的模型解密与正文揭示决定档案播放策略，画质设置独立生效。

## 五、支持格式

VLC 内核：由 VLC 决定（本机实测发行版支持 mp3/flac/m4a/ogg/opus/wav 等常见格式，另含 VLC 自带的其他解码器）。
浏览器内核：取决于浏览器，通常为 mp3/aac/flac/wav/ogg。

## 六、故障排查

| 现象 | 处理 |
| --- | --- |
| 设置里显示「未检测到本地桥接服务」 | 先确认音乐服务窗口在运行；再核对端口与令牌 |
| 「桥接响应超时（可重试）」 | 页面本身负载很高时会重试；稍候或点「连接桥接」再试 |
| VLC 控制接口无响应 | 多半是 VLC 装在了含非 ASCII 的路径；重跑 `fetch-vlc.mjs` 或把项目移到英文路径 |
| 播放停在「加载中」 | VLC 打开文件较慢（磁盘或 CPU 忙）；桥接会在就绪后自动推进 |
| 改了音乐目录 | 在音乐面板添加新的文件夹预设并切换；也可停止服务后以新 --root 启动 |
| 曲目显示失效 | 文件被移动或删除；重新扫描会移除 |

## 七、相关文件

- `scripts/start-rhine.mjs`：统一启动网页与可选 VLC 桥接
- `scripts/fetch-vlc.mjs`：获取并校验 VLC 官方发行版
- `scripts/vlc-bridge.mjs`：本地桥接服务（VLC 生命周期、曲库扫描、播放控制、PCM 频谱）
- `scripts/check-vlc-bridge.mjs`：桥接协议自检（`node scripts/check-vlc-bridge.mjs`）
- `启动莱茵科技.cmd`：推荐的网页 + 音乐统一入口
- `启动终端.cmd`、`启动音乐服务.cmd`：仅网页／仅桥接兼容入口
- `src/music-*.ts`：网页侧曲库、检索、播放器、桥接客户端与界面
- `verification/LOCAL-MUSIC.md`：验证记录
