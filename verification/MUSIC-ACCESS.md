# 音乐按需准备与档案揭示验证

日期：2026-10-11（Asia/Shanghai）。环境：Windows、Node.js 24.18.0、Edge 155.0.4283.45、VLC 3.0.21。样本使用项目原创配乐及生成正弦音，不读取个人曲库。

## 实现与覆盖

曲库扫描建立全部元数据索引。打开音乐档案后，只准备选中的音频；文字保持黑条，场景与返回操作可用。音频就绪后运行原有解密与文字揭示，二者完成的动画帧调用 `startPrepared()`。失败保留黑条并显示重试；返回、重新选曲、停止、销毁和内核切换使旧请求失效。

浏览器使用暂停的媒体元素等待可播放状态；VLC 使用静音、暂停准备和一次性开始票据。准备失败或停止恢复用户音量。面板直接播放沿用相同准备接口；系统媒体键路由到当前内核，切换内核先停止旧输出。

扫描保存采用完整事务；来源更换、取消、恢复和异步封面回填均检查所属请求。新选择的来源重新读取标签，同来源重复扫描复用未变化内容。搜索返回全部匹配曲目，面板分批显示 240 条。封面对象 URL 默认预算为 384 项，保留可见、选中、播放和解码租约持有的条目；其余条目按最近使用回收。

## 证据与边界

本地日志：`.local/check-2.5.log`、`.local/build-2.5.log`、`.local/e2e-music-2.5.log`、`.local/e2e-vlc-2.5.log`、`.local/vlc-protocol-2.5.log`。首轮失败诊断保留在 `.local/e2e-vlc-2.5-attempt1.log`。

- 对齐的是最后揭示帧中的播放调用；浏览器、VLC HTTP 服务与声卡仍有缓冲或通信延迟，未做音频回环测量，不能承诺实际出声的采样级同步。
- 无头软件渲染用于验证行为和截图，不代表真实设备帧率或听感。构建仍提示主 JS 包大于 500 kB；页面仍有 Three.js 阴影类型弃用提示。
- 页面行为检查使用小窗口及轻量渲染，保留完整解密和文字揭示动画；截图时暂时扩大窗口。该测试设置用于避免托管环境的软件渲染阻塞读取和播放回调，不作为默认画质或帧率证据。
- Windows CI 已加入 Edge、官方 VLC SHA256 校验、协议及顺序 UI 检查与证据上传。本记录为推送前的本地验证；远端检查结果以 GitHub Actions 为准，未执行部署。
- 托管 Windows 环境无声卡，CI 用 `RHINE_VLC_AOUT=dummy` 验证真实 VLC 解码、PCM 频谱和播放控制；该输出不支持实际音量回读。协议检查仍验证准备期间的用户音量保留，播放及停止后的实际音量断言保留在默认的本机真实输出检查中，CI 不作为声卡音量或听感证据。
