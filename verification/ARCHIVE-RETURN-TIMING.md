# 三维档案归位计时 · 2026-10-13

本次修复低帧率下归位持续变慢的问题。测试环境为 Windows、本机无头 Edge、Node.js 和 VLC 3.0.21；远端结果单独记录，不将本地通过写成 GitHub Actions 已通过。

## 原因与改动

原 `ArchiveScene.update` 将每帧经过时间限制为 0.05 秒。60 FPS 时无明显问题；10 FPS 已丢掉一半时间，8 秒一帧则仅推进 0.05 秒。此前远端运行 `38260385902` 在 240 秒内仍未归位，最后的音频交接断言没有执行。

- 解析弹簧与指数插值使用实际活动时间，不增加模拟循环或额外绘制。
- 按角度阈值计算转正耗时，主卡片和独立归位副本只将转正后的剩余时间用于下降。转正期间保持世界高度。
- 新输入记录自身起点，不能消耗输入前的长绘制时间；各副本保留独立起点，连续输入不重置已有副本。
- 页面显隐、360° 查看器和壁纸宿主暂停重置帧时钟。恢复首帧不补算暂停期间；相同时间戳不重复推进。
- 保留原有模型、材质、归位阈值、弹簧速度、快速反向继承和音乐揭示门控。

对照了 [Rhine-Music-Demo 的归位阶段与状态门控](https://github.com/RonaldDeng/Rhine-Music-Demo/blob/a889801f7f99993ee23b40e97efdeac6ad04a9be/src/music-camera.ts)。该参考提交的 [场景更新](https://github.com/RonaldDeng/Rhine-Music-Demo/blob/a889801f7f99993ee23b40e97efdeac6ad04a9be/src/scene.ts#L1311) 也限制每帧 0.05 秒，因此没有直接移植其低帧率处理。本次未复制参考模型或其他资源，未运行上游测试。
