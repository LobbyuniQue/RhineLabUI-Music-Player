# 基线与实验开发

2026-10-20 起，以当前版本建立 `basic` 基线，后续工作先作为实验推进。

## 分支用途

| 引用 | 用途 |
| --- | --- |
| `basic` | GitHub 默认分支，保存通过验收的基线，供日常使用与下载 |
| `experimental` | 后续实验开发的工作分支，功能和体验可能继续调整 |
| `experiment/<主题>` | 需要独立比较或并行尝试时，从当前 `basic` 建立的专题实验分支 |
| `basic-0.1.5-20261020` | 本次基线固定标签，保留最初的恢复点 |
| `main` | 保留既有公开提交与历史链接；新开发以以上分支约定为准 |

`basic` 分支会随验收通过的改动前进；已公布的基线标签保持固定。源码版本目前仍为 `0.1.5`，分支名称表示开发阶段，不另造一个软件版本号。

## 开始实验

1. 确认工作区已有改动的归属，在 `experimental` 或独立 `experiment/<主题>` 分支提交。
2. 在任务或 Pull Request 中写清要改善的行为、如何比较效果，以及需要保留的既有行为。
3. 使用本机 `.local/` 保存即时截图、日志与生成样本。长期验证结论写入 `verification/`，并注明提交、环境和未验证范围。

实验提交可以推送到同名分支供比较。打开目标为 `basic` 的 Pull Request 后，GitHub Actions 执行基础检查、构建与 Windows 音乐集成；需要提前运行远端验证时可手动运行该工作流。

## 转为基线

满足以下条件后，将实验通过 Pull Request 合入 `basic`：

- 目标行为达到任务约定的效果，相关使用流程完成实际检查；涉及视觉和听感时，静态检查或 dummy 音频输出不能替代对应验收。
- `npm run check` 与 `npm run build` 通过；音乐交互改动按工程约定完成浏览器与 VLC 两条路径的验证。
- Pull Request 对应的 `verify` 与 `Windows browser and VLC integration` 两项检查通过。VLC 下载、校验成功与后续测试通过分别记录。
- README、变更说明与验证记录反映最终实现。需要发布新版本时同步更新 package.json 和 package-lock.json，并建立新的固定基线标签。

测试通过但体验尚未达到目标的改动继续留在实验分支；只合入达到验收条件的内容。通过分支保护要求 Pull Request 和上述检查，保留单维护者无需额外审批人的工作方式。

## 回到基线

需要运行当前已验收版本时切换到 `basic`。需要对照本次原始基线时检出 `basic-0.1.5-20261020`，或从该标签建立独立分支。切换前先提交或妥善保存工作区改动。

实验不符合预期时保留实验分支作比较；已合入的回归通过新的修复或 revert 提交处理，保留已有历史与固定标签。
